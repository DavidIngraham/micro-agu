# Joint mechanics explanation

The first view uses prescribed isolated-axis rotations, not integrated free responses. Torque samples are generated by `sim_core::joint::joint_loads`, also called by the plant. Positive relative angle is canopy ahead of payload; the displayed torques act on the canopy and the payload receives their opposites. The lower spring/dashpot circuit is an angular-domain equivalent; its horizontal symbol movement is not translation of the point joint.

The second view illustrates the reduced bifilar energy construction using fixed equivalent connection lengths. The canopy is fixed while the payload twists with opposite signed angle. Its geometric rise is not an extra positional degree of freedom implemented by the plant. The stored preset has geometry yaw disabled; compare its fitted linear law with the optional nonlinear geometry law, not two contributions added together.

Regenerate from the repository root:

```sh
cd simulation
cargo run -q -p sim-io --example joint_explanation -- data/presets/as-built-trout-lake-sitl.json > ../viewer/apps/applets/joint-mechanics/loads.json
```

The build bundles the recorded dataset. Publish with the normal viewer manifest and `--app joint-mechanics`. All mathematical derivations live in adjacent blog Markdown and use its shared MathJax renderer. The applet only presents parameter values, labels and plotted recorded data.

The current upper support spacing is fitted. Neither it nor the nominal 850 mm height should be presented as independently measured. The 132 mm lower spacing is as-built. The full canopy outline is contextual; the model's effective support pair is not its wing tips. Motion honors reduced-motion preferences and can be paused/scrubbed.
