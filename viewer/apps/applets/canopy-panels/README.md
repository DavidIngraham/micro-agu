# Five-panel canopy explanation

This applet uses the shared viewer lifecycle and Three.js rendering resources. It displays frozen loads generated by the Rust plant, not a second JavaScript aerodynamic model. The embedded JSON is an explicit recorded explanatory dataset.

Regenerate from the repository root:

```sh
cd simulation
cargo run -q -p sim-io --example canopy_panels -- data/presets/as-built-trout-lake-sitl.json > ../viewer/apps/applets/canopy-panels/loads.json
```

The panel diagnostic kernel is also used by the dynamics solver. The generator reports the additional whole-canopy moment terms at the specified zero-rate, zero-sideslip condition. Do not reuse that reduced expression for arbitrary states.

The main wing adds illustrative trailing-edge droop using the shared `brakeOffset` renderer (2.5× edge-travel convention), with a dashed neutral edge. The local airfoil outline is schematic and uses that same deformation function; it is not a solved profile. Forces still use the rigid panel reference positions and frames. The disabled tilt term is a rotation about the forward/roll axis, not pitch incidence. the front inset depicts effective aerodynamic panel inclinations, including the optional differential-brake tilt when enabled. The recorded as-built preset sets `brake_tilt_rad_per_m` to zero, so both cases retain the same inclinations. The applet explicitly reports this setting. Panel numbers run aircraft left to right. Arrow lengths are quantitative, with separate force and velocity scales. The enlarged local inset projects vectors into its chord-normal plane, so it omits lateral components; numerical lift/drag magnitudes include all components. Inputs are effective brake travel, after actuator/rigging effects. No physical equilibrium is asserted.

Build and publish through the normal viewer manifest with `--app canopy-panels`. Blog math remains in adjacent Markdown and uses the shared MathJax renderer.
